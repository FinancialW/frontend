# commit-push

이 저장소(`FinancialW/frontend`)에서 작업이 끝났을 때, 변경사항을 **컨벤셔널 커밋 메시지로 커밋하고 곧바로 원격에 푸시**하는 스킬이다. 한국어로 응답한다.

## 사전 확인

먼저 현재 상태를 파악한다. 아래를 병렬로 실행한다.

```bash
git status
git diff --stat
git diff            # 스테이징되지 않은 변경
git diff --cached   # 이미 스테이징된 변경
git log --oneline -5
git branch -vv      # 현재 브랜치의 upstream 연결 여부 확인
```

- 변경사항이 하나도 없으면(워킹 트리가 깨끗하면) 커밋하지 말고 "커밋할 변경사항이 없다"고 알리고 종료한다.
- 원격(`origin`)이 `FinancialW/frontend`가 맞는지 `git remote -v`로 확인한다. 다르면 진행하지 말고 사용자에게 알린다.

## 커밋 절차

1. **변경 내용을 읽고 의미를 파악한다.** `git diff` 결과를 보고 무엇이/왜 바뀌었는지 이해한다. 변경이 성격상 여러 갈래(예: 기능 추가 + 무관한 설정 변경)면, 논리적으로 나눠 여러 번 커밋하는 것을 고려한다. 보통은 한 번의 커밋으로 충분하다.

2. **의도하지 않은 파일을 점검한다.** 빌드 산출물·대용량 생성 폴더(예: `android/`, `ios/`, `node_modules/`), 비밀키, 로컬 설정 등 커밋하면 안 될 것이 스테이징 대상에 섞여 있는지 확인한다. 의심스러우면 `git add -A`로 전부 담기 전에 사용자에게 한 번 확인한다. `.gitignore`에 이미 잡혀 있다면 그대로 진행한다.

3. **스테이징한다.** 보통은 `git add -A`. 일부만 담을 거면 경로를 명시한다.

4. **컨벤셔널 커밋 메시지를 작성한다.** 형식은 `<type>: <한국어 요약>`.
   - 타입(type)은 영어 소문자, 요약 설명은 **한국어**로 쓴다(이 저장소 기존 커밋 컨벤션: 예) `feat: 검색 기능 및 자동완성 기능 구현`).
   - 요약은 50자 내외, 명령형/평서형으로 간결하게. 마침표는 생략.
   - 필요하면 빈 줄 뒤에 본문(왜 바꿨는지, 주의사항)을 덧붙인다.
   - 자주 쓰는 타입:

     | type | 용도 |
     |------|------|
     | `feat` | 새 기능 |
     | `fix` | 버그 수정 |
     | `chore` | 빌드·설정·잡일(코드 동작 무관) |
     | `docs` | 문서(README, 주석, CLAUDE.md 등) |
     | `refactor` | 동작 변화 없는 구조 개선 |
     | `style` | 포맷·세미콜론 등 비기능적 변경 |
     | `test` | 테스트 추가/수정 |
     | `perf` | 성능 개선 |
     | `build` | 빌드 시스템·의존성(package.json 등) |
     | `ci` | CI 설정 |

   - 범위를 붙이고 싶으면 `feat(detail): ...`처럼 괄호 스코프를 쓸 수 있다(선택).

5. **커밋한다.** 멀티라인 메시지는 heredoc으로 전달한다. 메시지 끝에 Co-Authored-By 트레일러를 붙인다.

   ```bash
   git commit -m "$(cat <<'EOF'
   feat: 변경 요약을 여기에

   필요하면 본문 설명.

   Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>
   EOF
   )"
   ```

## 푸시 절차

6. **푸시한다.** 현재 브랜치를 원격에 올린다.
   - upstream이 이미 연결돼 있으면(`git branch -vv`에 `[origin/...]` 표시): `git push`
   - upstream이 없으면(현재 `feat/candle`처럼): 현재 브랜치 이름으로 upstream을 설정하며 푸시한다.

     ```bash
     git push -u origin "$(git rev-parse --abbrev-ref HEAD)"
     ```

7. **기본 브랜치 보호.** 현재 브랜치가 `main`이면 곧바로 `main`에 푸시하지 말고, 먼저 사용자에게 알린다. 기능 브랜치를 새로 파서 푸시하고 PR로 머지하는 흐름을 권한다(`git switch -c feat/<주제>` 후 푸시). 사용자가 `main` 직접 푸시를 명시적으로 원하면 그때 진행한다.

## 마무리 보고

8. 결과를 한국어로 간단히 보고한다: 만든 커밋 해시와 메시지, 푸시한 브랜치, 원격 위치(`FinancialW/frontend`). 푸시 후 PR 생성 링크가 출력되면 함께 안내한다.

## 주의

- `--no-verify`로 git 훅을 건너뛰지 않는다. 훅(lint 등)이 실패하면 원인을 고치고 다시 시도한다.
- 강제 푸시(`--force`)나 히스토리 변경은 사용자가 명시적으로 요청할 때만 한다.
- 비밀정보가 디프에 보이면 커밋을 멈추고 사용자에게 알린다.
